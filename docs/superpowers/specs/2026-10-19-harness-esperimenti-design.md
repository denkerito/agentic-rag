# Design: experiment harness (resume, metrics, statistics)

Status: approved · 2026-10-19

## Context and why

Today the evaluation harness runs **one battery at a time** (`python -m agentic_rag.eval`).

**What went wrong:** the semantic search ablation experiment (10 batteries) died twice halfway through, losing everything it had already run. Meanwhile, Gemini was returning 5xx errors that got mixed up with agent failures.

**What we need:** two experiments lasting hours, which get to the end and produce defensible numbers.
1. **Decision experiment:** keep semantic search or not. It runs after choosing the final model, still to be evaluated.
2. **Final benchmark:** the metrics to cite in the CV, with the project frozen and on a new test set written by the user.

**Goal:** a harness that
- treats the experiment (variants × repetitions × questions) as a unit;
- saves each run as soon as it finishes and resumes from where it stopped;
- separates infrastructure errors from agent failures;
- computes a small set of metrics with standard names and confidence intervals.

## Goals

1. **Resume:** an interruption costs at most the run in progress.
2. **Reproducibility:** the manifest ties the experiment to the code and to the ground truth; resuming is refused if they changed.
3. **Generic variants:** configurations (model, semantic search), so the same command serves the ablation **and** model comparisons.
4. **Infrastructure errors** handled with policy B and three safeguards (below).
5. **Metrics:** the chosen ones (below), with explicit denominators, 95% intervals and paired comparisons.
6. **Request limiter**, optional and provider-independent, that always measures the waits (approach 1).
7. **Judge validation** with Cohen's κ on human labels, without the assistant seeing the ground truth.

## Non-goals

- The content of the new test set: the user writes it. The harness works with any set that follows the current schema.
- Parallel execution, dashboards, a web interface for the results.
- An adaptive limiter or reading the providers' rate-limit headers.
- Changes to the `ok` criterion (`calcola_esito`): it stays the one of the ablation protocol.
- Excluded metrics: Citation Precision (noisy), Numeric Groundedness (too many false positives, postponed), Recall@k/MRR/nDCG (they need a separate retrieval benchmark), pass@k.

## Anti-goals

- Choosing or redefining metrics **after** seeing the results.
- A result better than reality because the hard questions were skipped (see safeguards).
- Ground truth content in public files, or read by the assistant (`AGENTS.md`).

## Concepts

- **Combination:** (variant, repetition, question). It is the unit of work, of resumption and of exclusion.
- **Run:** one attempt at a combination. It can end in three ways:
  - `completata`: there is an `ok`/`ko`/`nd` outcome;
  - `fallita_agente`: request limit, invalid answer after the retries, timeout on working time;
  - `errore_infrastruttura`: network, 429, 5xx after the SDK's retries.
- A combination is **closed** when it has a `completata` or `fallita_agente` run. With only `errore_infrastruttura` it stays **open**.

## Interface (CLI)

```bash
# create the experiment
python -m agentic_rag.eval.esperimento esegui --etichetta esp-ricerca-a \
    --variante con:semantica=1 --variante senza:semantica=0 \
    --ripetizioni 5 --judge [--judge-model M] [--pausa 5] [--tentativi-finali 2] \
    [--criterio "task_success_rate:con-senza>=10"]

# resume it (parameters taken from the manifest: refused with --variante, --ids, --criterio or --timeout)
python -m agentic_rag.eval.esperimento esegui --etichetta esp-ricerca-a [--pausa 5] [--tentativi-finali 2]

python -m agentic_rag.eval.esperimento riepilogo --etichetta esp-ricerca-a
python -m agentic_rag.eval.esperimento etichette --etichetta esp-ricerca-a --campione 30
python -m agentic_rag.eval.esperimento kappa --etichetta esp-ricerca-a
```

- **Variant keys:** `modello` (default `AGENT_MODEL`) and `semantica` (default 1).
- **Judge:** one for the whole experiment, because all variants must be judged the same way.
- The current CLI `python -m agentic_rag.eval` stays for quick trials. `eval.confronta` is removed: `riepilogo` replaces it.

## Persistence

| What | Where | Content |
|---|---|---|
| Manifest | `eval/reports/esperimenti/<etichetta>/manifest.json` | See below |
| Public runs | `.../<etichetta>/esecuzioni.jsonl` | One line per run, appended and written to disk as soon as it finishes: combination key, attempt, state, outcome, per-run metrics (counts and fractions only, like `riga_pubblica`), usage, times, error |
| Private runs | `eval/reports/private/esperimenti/<etichetta>/esecuzioni.jsonl` | In addition: question, expected answer, details (already git-ignored) |
| Summary | `.../<etichetta>/riepilogo.md` + `riepilogo.json` | Generated by `riepilogo`, never by hand |
| Labelling sheet | `eval/reports/private/esperimenti/<etichetta>/etichette.csv` | Private |

**Manifest content** (written at creation, checked at every resume):
- label, creation date;
- **hash of the `src/` tree at the current commit** (`git rev-parse HEAD:src`). Refused if `src/` has uncommitted changes; changes outside `src/`, such as the reports or the README, do not block;
- variants, repetitions, judge model, criterion;
- limits: `AGENT_MAX_REQUESTS`, timeout, `SEARCH_MAX_DISTANCE`, `ELENCO_PER_PAGINA`, `TESTO_MAX_K`, RPM/TPM;
- **sha256 of the ground truth files** (hash only) and the list of question IDs.

If something does not match on resume, the command stops and says *which keys* differ, without showing ground truth values.

## Execution

1. **Order:** for each repetition, for each variant, for each question. Variants alternate, so a period when the provider misbehaves hits them all the same way.
2. **Resume:** closed combinations are skipped.
3. **Infrastructure errors (policy B with safeguards):**
   - during the main loop: one immediate retry after the pause, as today;
   - **safeguard 1:** once the loop is over, a final pass retries the combinations still open, up to `--tentativi-finali` times (default 2). Combinations that stay open are **excluded** and reported in the summary.
4. **Timeout:** measured on **working time**, i.e. real time minus the limiter's waits, with the current default of 300 s.
   - Hitting it is an agent failure (`fallita_agente`), with its own `TempoScaduto` exception.
   - `errore_di_infrastruttura` in `src/agentic_rag/eval/runner.py` is fixed: today it treats every `TimeoutError` as infrastructure. Network timeouts (`httpx.TimeoutException`) stay infrastructure.
5. **Data collected for each run,** in addition to the current `RisultatoDomanda` fields:
   - input and output tokens (`result.usage`);
   - seconds of limiter waits;
   - working time;
   - **answers rejected by the validator, by reason**: the `RetryPromptPart`s of the output tool in `result.all_messages()` are counted. The reason is recognised by constants defined in `src/agentic_rag/agent/agent.py` next to `check_risposta`: sources never seen, number without sources, documented cause without a document;
   - **documents retrieved**: `doc_ids` from the trace of `cerca_testo` and `cerca_semantica`, plus the `doc_id`s opened with `apri_documento`. `elenca_documenti` does not count: it lists, it does not retrieve.

## Request limiter (approach 1)

- **Structure:** a Pydantic AI `WrapperModel` around any model, applied in `build_model` (`src/agentic_rag/agent/model.py`). It works for any provider.
- **Configuration:** `AGENT_RPM`, `AGENT_TPM`, `JUDGE_RPM`, `JUDGE_TPM`. **Not set means the limiter is off**, but the waiting time (zero) is still measured.
- **How it works:** a 60 s sliding window.
  - Before a request it waits if the RPM would be exceeded, or if the tokens used in the window have reached the TPM (counted from the actual usage of the responses).
- **State:** one instance per model name, at process level. `build_model` is called for every question and the window must not restart from zero.
- **Provider retries:** 429, 5xx (500, 502, 503, 504) and network errors are retried by `ModelloGestito` (`src/agentic_rag/agent/tentativi.py`), not by the provider's client: 5 attempts, pauses of 10, 20, 40, 60 s plus up to 1 s of jitter, a 120 s timeout per attempt. Every attempt goes through the limiter. The duration of failed attempts and the pauses go into `attesa_s` (excluded from working time); `tentativi_provider` counts the failed attempts per run. Known limit: an attempt in progress counts as work until it fails, at most 120 s. Other providers also keep their own SDK's `max_retries`.

## Metrics

Each metric is computed **only where it applies**, and the summary always states the denominator.

| # | Metric | Definition | Applies to |
|---|---|---|---|
| 1 | **Task Success Rate** | Runs with outcome `ok` ÷ closed runs (`fallita_agente` counts as a failure) | all questions |
| 2 | **Answer Accuracy (LLM-as-a-judge)** | `corretta` verdicts ÷ judged runs; the `parziale` share is also reported. A judgement that failed after the retries is excluded and counted | questions with an expected answer, judge on |
| 3 | **pass^k** (k=3) | Mean over questions of C(c,k)/C(n,k), with n closed runs and c successful | questions with n ≥ k |
| 4 | **Source Citation Recall** | Mean of `id_trovati / id_attesi` (`MetricheFonti`) | questions with expected IDs |
| 5 | **Numeric Exact Match Recall** | Mean of `MetricheNumeri.recall` | questions with an applicable expected query |
| 6a | **False Acceptance Rate** | Runs with `causa_documentata=true` ÷ runs on questions with an undocumented cause | modes `onesta` and `non_rispondibile` |
| 6b | **False Abstention Rate** | Runs with `causa_documentata=false` ÷ runs on questions with a documented cause | mode `normale` with at least one `DOC-*`/`CTR-*` among the expected IDs (derived from the structure) |
| 7 | **Guardrail Intervention Rate** | Runs with at least one validator rejection ÷ runs; plus the total rejections by reason | all |
| 8 | **Session Evidence Recall** | Expected documents (`DOC-*`/`CTR-*`) retrieved ÷ expected documents | questions with expected documents |
| + | **Efficiency** | Input and output tokens, requests and tool calls per investigation (averages); p50/p95 working time; cost per investigation from a per-model price table in the configuration (n/a if the model is not in the table) | closed runs |

In the summary every metric is reported **per variant**, **per mode** and in **total**.

## Statistics

- **Aggregation:** first per question (mean of its runs), then mean over questions, which all weigh the same.
- **95% interval:** percentile bootstrap resampling the questions, B = 2000, with a fixed seed so summaries are reproducible.
- **Comparison between variants:** paired bootstrap on the difference, computed **only on the combinations closed in both** variants (safeguard 2).
- **Pre-registered verdict:** if the manifest contains a criterion, the summary evaluates it on the paired combinations.
  - Format: metric, variant, reference, threshold in points.
  - For the ablation: Task Success Rate, `con` − `senza` ≥ 10 points. The verdict uses the point estimate as per the protocol; the interval is shown next to it.
- **Validity (safeguard 3):** the experiment is declared **invalid** and no verdict is issued if:
  - a variant has more than 10% of its combinations excluded, or
  - the share of exclusions differs between two variants by more than 5 points.

  The excluded combinations are always listed (variant, repetition, question ID).

## Judge validation (Cohen's κ)

- **`etichette`:** draws a sample stratified by mode and variant, with a fixed seed, from the judged runs. It writes it to the private CSV: question, expected answer, the agent's conclusion, documented cause and limitations, and an empty `etichetta_umana` column.
  - **The judge's verdict is not in the sheet:** labelling is blind.
  - The user fills it in.
- **`kappa`:** compares the human labels with the judge's verdicts and computes:
  - Cohen's κ on the three classes;
  - κ on the binary version (correct / not correct);
  - percentage agreement.

  It writes **only these numbers** to the public summary. The assistant does not open the CSV.

## Implementation order (summary of the plan that will follow)

1. Limiter and rejection constants (agent).
2. Extension of `esegui_domanda`: working-time timeout, new data collected, error classification.
3. `statistica.py` and `metriche.py`, with unit tests on known values (pass^k, κ, seeded bootstrap).
4. `esperimento.py`: manifest, JSONL, order, resume, final pass.
5. `riepilogo.py` (validity, pairing, verdict) and `etichette.py`.
6. Removal of `confronta`, documentation.

## Verification

- **Unit:**
  - statistical functions on hand-computed cases;
  - per-run metrics, including the cases where they do not apply;
  - validity and pairing with synthetic JSONL;
  - a manifest that refuses changes to `src/` and to the ground truth;
  - limiter with a fake clock.
- **Integration** (real DB and a fake `FunctionModel`, as in `tests/test_eval_integration.py`):
  - an experiment with 2 variants × 2 repetitions × 2 questions interrupted halfway (simulated `KeyboardInterrupt`) and resumed, with no duplicates and no lost runs;
  - a simulated 503 that leaves the combination open and is recovered in the final pass;
  - a working-time timeout counted as an agent failure.
- **Short real trial:** 2 questions × 2 variants × 1 repetition with the configured model, interrupted by hand and resumed. Then `riepilogo` to eyeball tables and denominators, without opening the private files.
- `pytest`, `pytest -m integration`, `ruff check`.
